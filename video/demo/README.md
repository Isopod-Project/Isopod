# Isopod demo video

A 48-second demo built from the **real dashboard**, not mockups. `stage.html` draws a Windows 11 desktop with a browser window. The browser's page is an iframe of the actual Isopod frontend, built from `frontend/src` with Vite. Playwright screenshots every frame, ffmpeg encodes them, and `audio.py` synthesizes the sound.

## How it stays deterministic

Isopod is a React app with its own state, so the video replays it:

- `inject/clock.js` replaces `setTimeout`, `setInterval` and `Date` with a virtual clock that only moves when the stage advances it. Polling and timestamps follow demo time.
- `inject/backend.js` replaces `fetch` for `/api/*` with an in-memory stand-in for the FastAPI backend. Its response shapes follow `backend/main.py`.
- `timeline.js` lists every click, keystroke and cursor move at a fixed time. `renderAt(t)` replays them in order, and reloads and replays from 0 if asked for an earlier time, so parallel workers produce identical frames.

Nothing goes to the network. Avatars and other external URLs are answered from `assets/` or with a 404.

## Commands

```
pip install playwright numpy scipy pillow imageio-ffmpeg
python make_assets.py            # stand-in icons and player heads (already committed)
python explore.py out/x.png      # load the app with the mock backend and screenshot it
python render.py stills 5 13.9   # single frames
python render.py sheet           # contact sheet per scene + out/overview.png
python render.py video 6         # out/isopod-demo.mp4
python render.py video 6 --portrait   # out/isopod-demo-portrait.mp4, 1080x1920 for Shorts/TikTok/Reels
python thumbnail.py              # out/thumbnail.png, 1280x720
python audio.py && python render.py mux   # sound only, without re-rendering frames
```

`render.py` rebuilds the frontend into `.appbuild/` whenever `frontend/src` is newer. Set `CHROME` to use another Chromium and `FFMPEG` to use another ffmpeg; by default it uses the one bundled with `imageio-ffmpeg`.

The portrait version uses the same events and sound with a different stage layout (`stage.html?layout=portrait`). The name and caption sit above the app, and the URL below it. The bands the Shorts and TikTok overlays cover are left empty. Its camera keyframes are `CAMERA_PORTRAIT` in `timeline.js`.

## Stand-ins

- **Data:** the servers, players (Pillbug, MossyCobble, Tater_Tot), IP address `203.0.113.24` (a documentation range), versions and logs are mock data.
- **Mod search results:** names and summaries follow the projects' Modrinth pages, and the Waystones dependencies (Balm, Fabric API) match its Fabric release. **Authors and download counts are rounded placeholders**, not live Modrinth numbers.
- **Icons:** server and mod icons and player heads are 8×8 pixel blocks generated by `make_assets.py`. They are not the projects' real logos or players' skins.
- **Thumbnail:** adds three more servers (Hardcore, Minigames, Modded) to the mock data so the dashboard looks in use.
- **Fonts:** rendered on Windows with the installed Segoe UI, the same font the dashboard uses there. No font files are committed.
